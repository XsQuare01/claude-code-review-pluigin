# Qualitative Rubric Review Rules

정성 코드 리뷰 전용 문서. 오직 `/code-review-qualitative`에서만 사용된다. 파일명에 숫자 prefix가 없으므로 일반 `/code-review` 자동 모듈 스캔에서 제외된다 (`math.md`/`fast.md`와 동일한 분리 방식).

이 문서는 라인별 위반을 잡지 않는다. diff 전체의 **정성 품질**을 LLM-as-a-judge 방식으로 축별 1~5점 채점한다.

## 직교성 (다른 모드와 겹치지 않음)

라인 버그·타입 오류·null 안전성·보안 결함 등 기계적으로 잡히는 결함은 **점수에 반영하지 않는다**. 그건 `/code-review`의 몫이다. 이 문서는 오직 아래 정성 축만 평가한다.

## 평가 축

### 축 A — 아키텍처 적절성

over/under-engineering 균형과 확장성. "변경 규모에 맞는 추상화인가."

| 점수 | 기준 (이게 보이면 이 점수) |
|---|---|
| 5 | 변경 규모에 딱 맞는 추상화. 현재 요구를 단순하게 충족하면서 합리적으로 예상되는 확장점만 열어둠. 불필요한 일반화·계층 없음. 책임 경계 명확 |
| 4 | 대체로 적절. 사소한 과/소추상화 1~2곳, 비용이 작고 쉽게 조정 가능 |
| 3 | 작동하지만 추상화 수준 애매. over(안 쓰는 일반화·조기 추상화)와 under(중복·확장 시 큰 수정 필요)가 공존 |
| 2 | 추상화 선택이 변경 의도와 어긋남. 불필요한 계층 도입으로 복잡도↑ 또는 확장 시 구조 전반 수정 필요 |
| 1 | 심각한 over/under-engineering. 변경이 시스템 이해·확장을 더 어렵게 만들고 잘못된 추상화가 전파됨 |

### 축 B — 일관성·관습 정합

주변 코드의 패턴·네이밍·디렉토리·에러처리·스타일과의 정합. "새 코드인지 기존 코드인지 구분되는가."

| 점수 | 기준 (이게 보이면 이 점수) |
|---|---|
| 5 | 주변 코드의 패턴·네이밍·디렉토리 배치·에러처리·스타일과 완전 정합. 새 코드인지 기존 코드인지 구분 안 됨 |
| 4 | 거의 정합. 사소한 컨벤션 일탈 1~2개(포맷, 사소한 네이밍), 의미 영향 없음 |
| 3 | 부분 정합. 일부 핵심 패턴(상태관리/에러처리/레이어링)에서 주변과 다른 방식을 도입했으나 국소적 |
| 2 | 여러 축에서 기존 관습과 충돌. 이질적 패턴이 여러 파일에 유입 |
| 1 | 관습 무시. 같은 문제를 푸는 기존 방식이 있는데 임의로 새 방식 도입, 일관성 붕괴 |

## 채점 정책 (점수 편향 억제)

LLM-as-judge는 점수가 3~4에 몰리고 근거 없이 후하게 주는 경향이 있다. 다음을 반드시 지킨다.

1. **관찰 가능한 기준**: 위 표의 "이게 보이면 이 점수" 기준에 실제 diff를 대조한다. "좋다/우수하다" 같은 형용사로 판단하지 않는다.
2. **근거 → 점수 순서**: 반드시 `근거(파일:라인 인용) → 점수` 순서로 작성한다. 숫자를 먼저 정하지 않는다.
3. **정수만**: 1~5 정수만. 소수점·범위 표기 금지.
4. **3에서 시작, 근거 있을 때만 ±**: 모든 축은 기본 3점에서 출발한다. diff에서 구체적 근거를 인용했을 때만 올리거나 내린다. 근거를 못 대면 3에 머문다.
5. **직교성**: 라인 버그·타입 오류는 점수에 반영하지 않는다.

## judge 출력 형식

각 judge sub-agent는 두 축 각각에 대해 아래를 출력한다.

```
### 축 A — 아키텍처 적절성
- 근거:
  - path/to/file.ts:42 — (판단 근거)
  - path/to/file.ts:88 — (판단 근거)
- 점수: 3
- 개선안: (점수가 4 미만일 때만 필수) ...

### 축 B — 일관성·관습 정합
- 근거:
  - ...
- 점수: 4
- 개선안: (점수 4 이상이면 생략 가능)
```

- 근거는 축당 1~3개. 반드시 변경된 파일/라인에서 인용한다.
- diff에 없는 기존 코드는 근거로 쓰지 않는다.
- 추측 금지. 근거를 못 대면 3점.

## 집계 / 판정 (오케스트레이터용)

5명 judge의 축별 점수를 모아 다음을 계산한다.

- **대표 점수 = 5개 점수의 중앙값(median)**. (정렬 후 3번째 값.)
- **spread = max - min**.
- **합의도**: spread ≤ 1 → 높음 / spread = 2 → 보통 / spread ≥ 3 → 낮음(주의, 별도 플래그).
- **판정**: 중앙값 ≥ 4 → 🟢 양호 / = 3 → 🟡 보통 / < 3 → 🔴 개선 필요.
- **머지 가능 여부**: 🔴(개선 필요) 축이 1개 이상이면 "수정 후 가능", 0개면 "가능".
- 대표 점수가 4 미만인 축은 5명의 개선안을 중복 제거·병합해 제시한다.
